## 1. Emergency Containment Actions (Immediate Execution)

### Step 1.1: Revoke Active IAM User Sessions

Attach an inline explicit deny policy to `dev-analyst` to kill all active AWS CLI/SDK sessions and block all incoming requests immediately.

````json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EmergencyExplicitDenyAll",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*"
    }
  ]
}

Step 1.2: Delete Attacker-Created Persistence Access Keys
Deactivate and delete both the original compromised Access Key and the back-door key generated by the threat actor.

```bash
# Deactivate and delete primary key
aws iam update-access-key --user-name dev-analyst --access-key-id AKIAIOSFODNN7EXAMPLE --status Inactive
aws iam delete-access-key --user-name dev-analyst --access-key-id AKIAIOSFODNN7EXAMPLE

# Deactivate and delete secondary back-door key
aws iam update-access-key --user-name dev-analyst --access-key-id AKIAI4444444EXAMPLE --status Inactive
aws iam delete-access-key --user-name dev-analyst --access-key-id AKIAI4444444EXAMPLE
Step 1.3: Detach Escalated Administrator Privileges
Strip the unauthorized AdministratorAccess policy from the identity.

```bash
aws iam detach-user-policy \
  --user-name dev-analyst \
  --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
2. Long-Term Remediation & Root Cause Prevention
Enforce Least Privilege: Replace inline administrative permissions with task-specific RBAC policies.

Mandate Short-Lived Credentials: Transition developers from long-lived static IAM Access Keys to AWS IAM Identity Center (SSO) or temporary web identity federation (STS).

Automate GuardDuty Containment: Deploy an AWS EventBridge rule triggered by high-severity GuardDuty alerts to invoke an AWS Lambda containment function automatically.

## 1. Executive Summary
On August 1, 2026, AWS GuardDuty alerted on anomalous API behavior originating from IAM user `dev-analyst`. Subsequent log analysis of AWS CloudTrail confirmed that an external threat actor used a compromised static Access Key (`AKIAIOSFODNN7EXAMPLE`) from IP `198.51.100.42` to establish persistence via secondary Access Key creation and escalate privileges by attaching the `AdministratorAccess` policy.

Immediate containment actions were taken to revoke user access, delete compromised keys, strip elevated policies, and apply an explicit deny boundary. No data exfiltration was detected during S3 bucket enumeration.
````
